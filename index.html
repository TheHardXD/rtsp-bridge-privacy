1. General information

This Privacy Policy explains how information is processed by RTSP Bridge.

RTSP Bridge is designed to receive RTSP video streams from network cameras and expose them as virtual camera devices in Windows, for use with applications such as Zoom.

The application is designed so that camera video processing takes place primarily on the user’s local device.

Tytus Borycki

3. Information the application may process

Depending on how RTSP Bridge is used, the desktop application may access or process:

  • IP addresses, host names, RTSP URLs, camera usernames and passwords required to connect to cameras,
  • technical camera information, stream profiles, live RTSP video, saved devices and application settings,
  • Microsoft Store subscription status and locally measured camera-stream usage,
  • diagnostic information that the user voluntarily sends for support.

Optional Google/Firebase account features (RTSP Bridge 0.4.0 and later): when the user signs in using Google, the Firebase service processes a unique Firebase account ID (UID), email address, display name where available, most recent activity timestamp, Premium entitlement and expiry, and aggregate app usage duration (total and current calendar month). Administrative changes to Premium are recorded in an audit log with the affected UID, the administrator UID and the change timestamp.

Account-linked usage is measured from periodic requests while the signed-in desktop app is open; it is distinct from the local Basic-plan camera-stream usage counter. The account-linked data does not contain RTSP video, camera passwords, stream contents or camera addresses.

4. Camera video

RTSP camera video is processed locally on the user’s computer in order to create a virtual Windows camera.

RTSP Bridge does not transmit camera video to servers operated by the publisher.

RTSP Bridge does not automatically record or archive camera video.

If the user uses RTSP Bridge together with third-party software such as Zoom, Microsoft Teams, or another application that receives video from the virtual camera, any further processing performed by that third-party application is governed by its own privacy policy.

5. Camera credentials

RTSP Bridge may store information required to reconnect to saved cameras, including RTSP addresses and authentication credentials.

This information is stored locally on the user’s device.

The application uses security mechanisms provided by Windows to protect stored authentication information.

The publisher does not receive or store passwords to the user’s cameras.

Users are responsible for securing their own local network, devices, and camera credentials.

6. Local network device discovery

If the user enables automatic camera discovery, RTSP Bridge may send local network discovery requests using technologies such as ONVIF or WS-Discovery.

Information obtained through local discovery is used only to identify and configure devices available on the user’s network.

This information is not automatically transmitted to the publisher.

7. Subscriptions, Premium entitlements and payments

Microsoft Store subscriptions and purchases, where offered, are handled through Microsoft Store. RTSP Bridge receives the subscription entitlement information needed to determine which features and limits apply.

Users who choose to sign in with a Google account may also receive Premium access assigned by an RTSP Bridge administrator. Firebase stores the applicable entitlement status, validity period and a record of administrative changes. An administrator-assigned entitlement does not require a purchase through Microsoft Store.

The publisher does not receive payment-card details or other payment credentials. Microsoft manages Store purchases, billing, renewal and cancellation under its own policies.

8. Usage measurement and account-linked records

The Basic plan may include limits on active virtual-camera streaming time. The local subscription usage counter measures camera-stream activity, not merely the time that the program is open.

Separately, when a user is signed in through Firebase, the application may send an authenticated activity heartbeat approximately every 30 seconds. The backend associates the resulting server-measured usage intervals with that user's Firebase UID. It stores the overall duration, the current-month duration and the date of the last heartbeat. These account-linked statistics reflect application activity and are not equivalent to the duration of RTSP video streaming.

Usage statistics are used to display account activity, administer service entitlements and help protect the service from misuse. Neither form of usage measurement requires the transmission of camera images, audio, RTSP passwords or stream contents.

9. Diagnostics and error reports

RTSP Bridge does not automatically send complete logs, camera video, or camera credentials to the publisher.

If the user chooses to report a problem, the user may voluntarily send diagnostic information by email to tytusborycki@gmail.com.

Before sending a support request, users should review its contents and avoid including passwords, access tokens, or other confidential information unless it is necessary to resolve the problem.

10. Purposes of processing

RTSP Bridge processes information to connect to selected cameras, display virtual cameras in Windows, preserve user configuration, discover devices on local networks and provide technical support.

When Firebase account features are used, additional processing supports Google sign-in, linking the desktop app to a Firebase UID, refreshing sessions, displaying Premium status, managing administrator-assigned entitlements, recording entitlement changes, displaying account usage statistics and protecting the service against unauthorized access.

Microsoft Store subscription information is processed to verify purchases and apply the applicable service limits.

11. Legal bases for processing

Where the General Data Protection Regulation (GDPR) applies, the legal basis depends on the specific purpose: performance of the app/service contract for authentication, entitlements and core functions; legitimate interests for service security, abuse prevention and responding to support requests; compliance with legal obligations where applicable; and consent where a particular processing activity legally requires it.

Google/Firebase sign-in is optional for local RTSP camera use, but is necessary to access account-linked Firebase features and administrator-assigned Premium.

12. Sharing of information and service providers

The publisher does not sell users' personal information. Data is disclosed only as needed to operate relevant features or meet legal requirements.

  • Microsoft: Microsoft Store distribution, subscriptions, licensing and payments, where applicable.
  • Google / Firebase: Google sign-in and Firebase Authentication; Firebase Cloud Functions to validate sessions and entitlements; Cloud Firestore to store Firebase UID-linked profiles, entitlements, aggregated usage and administrative audit records; Firebase Hosting for account login and the administrative panel.
  • Public authorities where disclosure is required by applicable law.

The video and audio from RTSP cameras are not sent to the Firebase backend for these account and licensing functions. Google and Microsoft process service data under their respective privacy terms.

13. Data retention and account deletion requests

Saved camera configurations, RTSP connection details and associated credentials remain locally on the device until changed or removed by the user or deleted with the application's local data.

When Firebase account features are used, Firebase UID-linked profile data, Premium entitlements, app-usage totals and audit events are held to operate the account, maintain service security and resolve disputes. An automatic fixed deletion period for these backend records is not currently specified. Users may request review or deletion of their account-related information by contacting tytusborycki@gmail.com. Some records may need to be retained longer when required by law or legitimate security needs.

One-time desktop sign-in sessions normally expire after a short validity period. Microsoft Store data and voluntarily provided support correspondence follow the relevant provider's terms and the time needed to address the request.

14. Security

RTSP Bridge uses security measures intended to reduce unauthorized access. Windows features are used to protect locally saved camera credentials. In the Firebase-enabled Windows app, the session refresh token is saved using Windows Data Protection API (DPAPI), scoped to the signed-in Windows user; the refresh token is not deliberately saved as plaintext.

Firebase API access requires a validated Firebase sign-in token, and administrator actions are restricted to authorized accounts. The backend stores account and usage information independently from camera-stream content.

However, no system guarantees absolute security. Users should secure their camera passwords, devices and local network and keep the software updated.
